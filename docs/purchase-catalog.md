# 購入候補カタログ

`src/lib/purchase-catalog.ts` の `purchaseCatalog` に、商品詳細ページを確認した候補を登録します。埋め込みやベクトルDBは使わず、部品種別・抵抗値・LED色・基板モデルなどの構造化条件で候補を取得し、既存の商品選定処理に渡します。

## 動作

1. 既に取得したDigiKey候補を確認。
2. 適合候補がなければ登録済みページを最大3件まとめて確認。Google Searchによる商品発見を省略。AmazonはURL Contextで商品ページを取得できないため、Amazonの登録候補は確認せず手動リンクとしてのみ表示。
3. 登録候補も確認できなければ既存のWeb検索（Amazonを除く国内ショップ）にフォールバック。確認済みのURLは再検索から除外。
4. 部品に検索リンク（`search: true`）が登録されている場合は、確認できる国内ショップに取り扱いがないとみなしてWeb検索を行わず、検索リンクからの手動購入を案内して終了。

登録情報だけで在庫あり・適合済みとは判定しません。ページ取得の成功、在庫、必要数量、入数、回路との適合性を確認できた商品のみ自動選択します。AIの利用上限やタイムアウトは既存の制限が適用されます。

購入モーダルの「登録済みの商品候補」は検索前や検索失敗時にも参照できます。未確認と明記した手動確認用リンクであり、カートには自動追加しません。DigiKey以外は販売店の商品ページを開きます。検索リンクは「〇〇の検索結果」と表示し、おすすめが見つからなかった部品の理由の横にも表示します。

## 追加方法

配列に一意な `id`、`name`、`store`、実在する商品詳細 `url`、`match`、`reviewedOn`、`enabled` を追加し、再デプロイします。管理画面・Firestore登録・自動学習は今回の実装には含みません。

- LED: `match: { kind: "led", color: "green" }`
- 抵抗: `match: { kind: "resistor", ohms: 10000 }`。330Ωと330kΩは別候補。
- 基板: `match: { kind: "board", board: "pico" }`
- ブレッドボード: `match: { kind: "breadboard" }`。400穴・30列を商品ページで確認。
- ジャンパ線: `match: { kind: "wire", value: "オス–オス" }`。部品表の表記（エンダッシュ `–`）と完全一致。
- その他: `match: { kind: "dht22", value: "回路BOMの正確な値" }`。センサー型番、ピン数、電圧、プルアップ、ヘッダー等を事前確認。`value` を省略すると、その種別のすべての部品に一致します（DHT22のように部品表の表記が揺れる場合）。

国内ショップで扱いがなく、商品ページを確認できない部品は、商品ページの代わりに販売店の検索ページを `search: true` で登録できます。現在はAmazon（`https://www.amazon.co.jp/s?k=キーワード`）のみ対応し、`storeSearchUrl` がHTTPS・ドメイン・`/s` パス・`k` パラメーターを検証して、キーワード以外のパラメーターを除去します。検索リンクは在庫・適合の確認を行わず、自動選択もしません。

価格・在庫は登録しません。`reviewedOn` は登録情報の確認日であり、現在の在庫確認日ではありません。販売終了や誤登録は `enabled: false` にします。同じURLは重複除外し、配列の先頭から最大3件を採用します。

登録商品は秋月電子の緑・赤LED、10kΩ高精度抵抗、カーボン抵抗4種（220Ω・330Ω・1kΩ・10kΩ、各100本入）、AM2302（DHT22）、オス–オスジャンパーワイヤ2種、ブレッドボード2種、ST7789 TFT液晶（131019）と、30ピンESP32 DevKit V1のAmazon検索リンクの計14件です。ST7789は `kind: "st7789", value: "M154-240240-RGB"` と完全一致すると候補に入ります。Editor追加時とAI生成指示はこの型番を標準値にしています。各URLはコード内に記載。10kΩの高精度品（10本パック）は用途・価格次第で自動選択されない場合があり、その場合も同じ10kΩのカーボン抵抗が候補に残ります。他の部品は従来の検索を継続します。

検証: `npm test`、`npm run typecheck`。商品・在庫確認の外部AI/API呼び出しは単体テストでモック化しています。
